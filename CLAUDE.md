# Pokémon Team Builder

- Stack: Vite + React 19 + TS strict + Tailwind v4 + Zustand. Domain logic lives in `src/domain/`, which has no React imports.
- Data: `npm run data` rebuilds `src/data/generated/*` (Champions, `gen1…gen9`, and `lgpe`/`bdsp`/`pla`/`za` from Showdown's game mods) from `@pkmn/dex` / `@pkmn/mods`, a pinned Showdown checkout (`scripts/sources.ts`) and `src/data/regulations/*.json`. Never hand-edit the generated files.
- Data audit: `npm run data:audit` (scripts/audit-data.ts, pure diff in `src/domain/dataAudit.ts`) compares the Champions data with Showdown's current Champions mods and writes `docs/data-audit.md` (generated); intended differences go in `scripts/audit-allowlist.json` with a reason; `-- --strict` fails on unexplained ones (a weekly Action opens one issue when there are). The Champions learnsets come from the pinned Showdown checkout (`scripts/sources.ts`, `scripts/lib/showdown-mods.ts`), not @pkmn/mods; bumping the pin refreshes the cache by itself.
- Pokédex: `npm run pokedex` rebuilds `pokedex-<book>.json` from PokeAPI CSVs + PKHeX encounter tables (pinned in `scripts/sources.ts`; run after `npm run data`); `npm run maps` rebuilds `public/maps/*.webp` + `maps.json` from the pret disassemblies and the hand-placed schematics in `src/data/maps/*.json` (those you may edit). Keep `gens.test.ts`' map-coverage test green.
  - Champions has no wild encounters and isn't in PokeAPI: `npm run pokedex:champions` (after `npm run data` and `npm run pokedex`) rebuilds `pokedex-champions.json`/`champions-learn.json` locally, reusing Gen 9's flavor text for the National Dex numbers Champions has. Its species list is filtered live to whichever regulation is selected (`Dex.selectableSpecies(regulationId)`), so a regulation change alone needs no rebuild.
- Atlas: `npm run atlas [-- game]` (scripts/build-atlas.ts, one builder per engine in `scripts/atlas/`: gen1, gen2, gba, platinum, hgss, dp; `encounters.ts` builds the encounters-only files for Generation 5 onward from the Pokédex data, `AtlasGame.lite`) rebuilds `atlas-<game>.json` (locations, items, NPCs, shops, every trainer's team; from the pret decompilations pinned in `scripts/sources.ts`) and `docs/data-gaps/<game>.md`. Sibling versions share a file (Blue → red, Silver → gold, Sapphire → ruby, LeafGreen → firered: `AtlasGame.file`). Run it after `npm run data`, `npm run pokedex` and `npm run maps`; its location ids are the `places` ids of `maps.json`. Never hand-edit the output; the map aliases (`PLACE_ALIASES` and section aliases in the builders) are the only hand-written mapping. Trainers no map places are kept in `unplaced` with a reason in `otherTrainers` (the Trainers page's *Other trainers*); wild-encounter places without a map are added by `addOffMapEncounterPlaces` (kind `roaming` or `landmark`, no pin) and sea routes that share a map point at it with `sameAs` (`scripts/atlas/common.ts`). `src/domain/atlasTypes.ts` is the file shape (shared with the script), `atlas.ts` the helpers, `src/components/atlas/` the UI. After a new atlas file, run `npm run sprites:items` (it adds the atlas' bag items and TM icons to the item atlas).
- Runs (Pokénav → Run, `src/domain/runs.ts`): `PLANS` writes out each full game's gym / Elite Four / Champion order by name (the atlas `badges` list isn't in game order); add a plan there when a game gets an atlas file, and keep `runs.test.ts` green. The store is `ptb:runs:v1` (`src/store/runStore.ts`, sanitised on load, migration tested).
- Sprites: `npm run sprites` rebuilds `public/sprites/*` atlases from PokeAPI.
- Meta data: `npm run meta` (scripts/build-meta.ts + `scripts/meta/`, pure parts in `src/domain/metaSources.ts`) rebuilds `src/data/generated/meta.json`: the game's own ranked Battle Data for the live season (daily, usage as a rank: `usageRank`, shown via `usageLabel`/`usageText`), Smogon's monthly stats, else provisional numbers from Limitless team lists, Showdown replays or the previous regulation (carry-over); a daily Action proposes updates. The app loads it on first use: read it through `useMetaFor()` (`src/data/useMeta.ts`), never a static import of `@/data/meta` (a test checks). See `docs/UPDATING_META.md`.
  - History: `src/data/generated/meta-history.json` (built by `npm run meta` with `scripts/meta/history.ts`; pure parts, trends and the break rule in `src/domain/metaHistory.ts`) is read lazily through `useMetaHistory()` (`src/data/metaHistoryData.ts` is never statically imported; a test checks). Never compare an in-game rank with a Smogon %: `computeTrends` measures inside one run.
  - Tournament teams: `src/data/generated/tournament-teams.json` (top cuts of Limitless events, built by `npm run meta` with `scripts/meta/tournamentTeams.ts`; `tournamentTeams.ts` is script-safe and pure, `tournamentImport.ts` needs the Dex) is read lazily through `useTournamentTeams()` (`tournamentTeamsData.ts` is never statically imported). Team sheets have no spreads: an imported team's spreads are estimates and say so.
- Regulation updates follow `docs/UPDATING_REGULATIONS.md` exactly.
- Phone app: PWA (`vite-plugin-pwa` + `src/pwa.ts`), hosted on Cloudflare Workers (`wrangler.jsonc`, auto-deploys on push) behind Cloudflare Access; see `docs/IPHONE_APP.md`.
- Cloud sync (web/PWA, and the desktop app once linked with a pairing code: `worker/devices.ts`, `src/domain/pairing.ts`, `src/sync/pairing.ts` + `deviceStore.ts`; `/api/device/*` must be a Bypass path in Access): `worker/` (the `/api/*` Worker: Access JWT check, D1) + `src/domain/sync*.ts` (merge rules, wire format) + `src/sync/` (client); setup, backups and the desktop options in `docs/SYNC.md`. `wrangler.jsonc` sets `main` and `run_worker_first: ["/api/*"]`; the D1 binding is added by hand after creating the database (a placeholder id would break the auto-deploy).
- Archetypes: `src/domain/archetypes.ts` detects them (thresholds in `ARCHETYPE_RULES`, only confident tags returned), `archetypeInputs.ts` feeds it from teams, logged teams and the meta, `roles.ts` is the support/control table shared with the bring planner. Never overwrite an archetype the user typed.
- Benchmarks and notes: `src/domain/benchmarks.ts` (light: types, `sanitizeBenchmarks`, `brokenCount`; safe in the first-load bundle) vs `benchmarkEval.ts` (heavy, damage engine: only through `useBenchmarkResults`'s lazy import); `PokemonSet.notes`/`benchmarks` and `Team.matchupNotes` travel in PTB1/share codes and sync (64 KB per document); `teamSheet.ts` + `src/components/team/TeamNotes.tsx`/`TeamSheet.tsx` (print CSS in index.css).
- Teammate suggestions: `src/domain/teamSuggest.ts` (weights in `WEIGHTS`, cheap scoring on all candidates, damage-engine threat component only on a `SHORTLIST_CAP` shortlist through the threat worker) with `components/team/SuggestTeammate.tsx`; never suggest anything illegal, honour the species/item clauses, note (don't forbid) a second Mega.
- Game day: `src/domain/gameday.ts` (pure: their six, speed order, the match it logs), `src/store/gamedayStore.ts` (`ptb:gameday:v1`, sanitised, migration tested), `src/components/gameday/GameDayView.tsx`; it reuses `planBring` (which also returns the 6×6 `matrix`), `PlanCard`, `BringPicker` and `LoggedMonDetails`. Only saved, own Champions teams can play.
- Navigation: the main bar's destinations (defaults, Champions swapping Pokénav for Reverse search, limits, More's contents) are `src/domain/navigation.ts` with the choice in `prefsStore.nav` (Settings → Navigation); views, Analyse tabs and URL hashes (with the pre-0.24 ones as redirects) are `src/domain/routes.ts`; `src/components/analyse/AnalyseView.tsx` (one team picker over its tabs), `CommandPalette.tsx` (Ctrl/⌘ K) and `WhatsNew.tsx`. What's new is built from `CHANGELOG.md` (`src/domain/changelog.ts` via `virtual:changelog`): keep `## x.y.z — date` headings and `### New/Changed/Fixed` bullets; a bold title that names a screen gets a Try it link (`destinationFor`). A new view needs a route, a palette entry and e2e (`e2e/navigation.spec.ts`).
- Releases: `npm run bump -- <version>` + a `CHANGELOG.md` section → PR into the default branch (`claude/pokemon-team-builder-otextg`, there is no `main`) → merge → `desktop-release.yml` tags `v<version>` and publishes the desktop installers by itself, to the separate public repository `Mernhil/pokemon-team-builder-releases` (the updater's endpoint; this repository can be private, docs/DESKTOP_RELEASES.md, docs/PRIVATE_REPO.md). Manual `v*` tags still work. One version bump per PR (two bumps in one merge leave the earlier one without a tag or desktop build), and every bump has a `## <version>` CHANGELOG section; CI fails a PR whose `package.json` version has none.
- Before any commit: `npm run typecheck && npm test`. Before a PR that touches UI: `npm run e2e` (Playwright smoke + axe tests on desktop Chromium and an iPhone-sized WebKit; `docs/E2E.md`). CI (`.github/workflows/ci.yml`) runs lint, typecheck, tests, build and e2e on every PR.
