# Polish plan (0.26.0)

An audit of the repository at version 0.26.0 for the polish phase: QOL, UI/UX consistency, accessibility, performance, small fixes and repo tidiness. **No source file was changed**; this document is the only output. Nothing here adds a feature.

How it was audited: static reading and `grep` of `src/`, `scripts/`, `worker/`, `docs/`; `npm run typecheck`, `npm run lint`, `npx vitest run`, `npm run build` (with the bundle budget); a sourcemap build to see what is in each chunk; `knip` (run from outside the repo, no config change); and a Playwright probe (iPhone 14 emulation on Chromium, a six-Pokémon team imported) that measured every visible control on each main route in both looks (Sticker and Classic). Numbers below come from those runs. Findings marked *(static)* were read from code and not yet seen on screen.

## Summary of the overall state

The codebase is in good shape. `tsc -b` is clean, **892 unit tests in 59 files pass**, lint has **0 errors and 18 warnings**, there is one conditionally skipped e2e test (a keyboard shortcut, phone only) and only two `TODO`s in the whole repo. The primitives in `src/components/ui/` are used widely (150 `<Button>` against 95 raw `<button>`), colours come from tokens (the only hard-coded hex colours in components are map drawing in `SchematicMap`, `AtlasMap`, `RegionMap`), contrast of the tokens is unit-tested and the palette generator is swept, `prefers-reduced-motion` is handled globally, and the dense grids already have good screen-reader text (cell sentences, captions, scroll regions). Most destructive actions already offer Undo.

The real problems are concentrated in a few places:

1. **A contrast bug in the default (dark) theme**: the active ＋/− nature buttons in the Stat Point calculator put white text on `bad`/`accent` colours at 2.4:1 and 2.5:1.
2. **A phone layout bug**: the Pokénav page scrolls sideways (403 px of content in a 390 px viewport in Sticker, 399 in Classic).
3. **Touch targets**: several families of controls are under 44 pt on a phone (Pokénav game chips, Pokédex type filters, Analyse/Meta tabs, the SP rows, 21 hand-rolled checkboxes).
4. **Bundle headroom is nearly gone**: first load is 249 KB of 260 KB (96 %) and the offline precache is 43.9 MB of 45.0 MB (97.5 %). The Threat worker alone ships a second copy of `@smogon/calc` and `champions.json` (1.09 MB raw, 200 KB gzip).
5. **Data loss paths**: deleting a logged match has no confirmation and no Undo; Pokénav progress reset uses a native `window.confirm`.
6. **Accessibility gaps beyond axe**: type matrices are mouse-only (`title` tooltips on non-focusable cells, while the help text says "hover or focus"), the type label is cut to 4 letters ("Figh", "Psyc") which a screen reader reads out, pinch-zoom is disabled, and axe only ever runs in the default Sticker look and default palette.
7. **Tidiness**: README and some docs have drifted (roadmap lists things that shipped; PWA size says ~17 MB, real precache is 43.9 MB), `toID` is re-implemented 11 times, an unused runtime dependency, 54 unused exports, 9 files over 500 lines in `src/`/`scripts/`.

**Not in this checkout:** the *Outlines* and *Brightness* appearance settings mentioned in the request do not exist at 0.26.0. Settings → Appearance has only the palette (hue + vividness, `src/domain/palette.ts`) and the Sticker/Classic *Style*. `git log --all` shows no branch with them. Their contrast/render audit (A11Y-09) is therefore written as a test to add *with* those settings; tell me if they live on a branch I should look at.

**Sync on the phone says "not set up on that deploy"** (reported while this audit ran). That message is the app's answer to HTTP 501 (`src/sync/http.ts:35`), and the Worker returns 501 when any of `DB`, `ACCESS_TEAM_DOMAIN` or `ACCESS_AUD` is missing (`worker/api.ts:80`, `:101`). In this repository `wrangler.jsonc` still has the `d1_databases` block commented out (`:21-22`), so the deploy has no database. This is the one-time manual setup in `docs/SYNC.md` steps 1–5 (create the D1 database, paste its id in `wrangler.jsonc` and push, apply the migrations, set the two Access variables); it needs your Cloudflare account, so I have not done it. See BUG-05 for making the message say which piece is missing, and open question Q1.

## Deferred feature request (not part of the polish phase)

- Keep the switch button as it is for Megas, and offer the same button for items. It appears by itself when the Pokémon's held item changes a stat; there is nothing to configure.
- The normal tab keeps the usual solid bars. A second, more transparent bar is drawn on top of each stat that changes, ending where the Mega or the item takes the stat to.
- Pressing the button swaps which of the two is solid and which is transparent, so you always see where the stat *was* (Base / no item) next to where it *is* (Mega / item).

Notes for whenever this is scheduled: it is new behaviour, so it waits until the polish phase is done.
